# API

## Overview

This is the document a consumer codes against. Every other spec owns a
behaviour; this one owns the wire: the routes, the action each one asks
the authorizer, the shape of every request and response, the errors, the
pagination, the conditional requests, and the OpenAPI description
generated from the code so a client generator and the server cannot
disagree.

Arca serves one surface, `/v1`, on the public listener of
[[002-repository-scaffold]], which also owns `GET /`, `/livez`,
`/readyz`, `/version`, and `/metrics`. Beside `/v1` sits one more public
document, `GET /openapi.json`. Every `/v1` route carries a bearer token
and asks before it acts ([[006-identity]]), with three exceptions named
below: the three link redemption routes, where the token in the URL is
the whole authorization ([[008-shares-and-links]]).

The service Arca replaces registered sixty routes across its handler
package. The surface here is forty-one routes under `/v1` plus that one
document. Three groups stay behind whole. Its webhook routes go with
webhooks, retired before drafting closed; a consumer tails the event log
instead ([[010-events-and-reaper]]). Its two quota routes go with the
stored limit; Arca counts usage and stores no limit, and the count is
read from the administrative overview ([[012-administration]]). Its
per-space administrative listings and its audit routes go with the
second set of handlers that answered them; an administrator asks the
owner's own route about somebody else's space ([[012-administration]]).
Nine more routes do not come across: eight belong to identity, to a
hosted platform's policy, or to one company's documentation site, and
one is answered differently by [[002-repository-scaffold]]. A further
one folds into a route that already existed. The rest are the same
routes, renamed where the grammar required it, plus the routes the
vocabulary of [[006-identity]] needed and the predecessor had not
written. The tables below are the whole surface, grouped by the spec
that owns each route's behaviour.

## Current state

The frame is built and in the tree on 2026-09-18, phase 2 of
[[019-migration-from-drive]]: `internal/api` holds the router, the error
table, the list envelope, the conditional request headers, the request
id, the two rate limits and the route table the mux and the document are
both built from; `internal/apidocs` builds the description; `tools/apidoc`
writes the committed `api/openapi.yaml`.

Four routes are registered. Three are the public link routes, because
their place is outside the verifier and registering them later would be
registering them somewhere else; they answer `not_implemented` until
[[008-shares-and-links]] lands their behaviour. The fourth is `GET
/v1/events`, the first row whose behaviour has landed: the handler is
[[010-events-and-reaper]]'s, and `internal/api/events.go` binds it to the
verifier, to `event.read` and to the error table. The other thirty-seven
rows of the table above arrive with the specs that own them, on the
phases of [[019-migration-from-drive]].

Criteria 6, 7, 8's envelope half, 9's header half, 13, 14 and 15 have
passing tests, and criterion 2's rule is proved against a recording
authorizer for a route of each kind. Criterion 1 is open by
construction: it closes when the last handler lands, and the route table
test reads the forty-one rows above and holds every registered route to
its row until then. Criteria 3, 4, 5, 10, 11, 12 and 16 wait for the
handlers and the stores of later phases. The spec stays at `testing`.

What the implementation decided, where this spec was silent or where the
tree made another reading better:

- The error table gains `not_implemented`, 501, whose row is above.
- `?limit=` outside `[1, 1000]`, and a value that is not a whole number
  at all, are `invalid_field`. This spec named the cap; the rest follows
  from the same sentence, and the silent clamp of the service Arca
  replaces is what it was written against.
- `If-None-Match` naming a checksum an object still has refuses a write,
  RFC 9110 section 13.1.2. The star form of the table above is that rule
  rather than a rule of its own: `*` matches whatever is there, so a
  write finds nothing or is refused.
- `If-Match: *` asks for anything that exists, which every write that
  finds an object already satisfies, so it is read as no condition.
- A weak validator in either header is `invalid_field`: every validator
  here is strong, and a caller that sent `W/` asked for a comparison
  this server does not make.
- A path under `/v1` that no row registers meets the verifier before it
  meets a 404, so whether a route exists is not something an
  unauthenticated caller learns.
- The request id is a ULID by its layout, forty-eight bits of
  milliseconds and eighty random, in Crockford base32. Nothing parses one
  back, so the encoder's bit alignment is the standard library's rather
  than the ULID specification's, and the id sorts by the order it was
  minted either way.
- The per-address rate limit is charged only where a request has no
  verified subject: a public link route, and a bearer the verifier
  refused. A caller that authenticates pays the per-subject bucket alone,
  which is what [[015-security-and-threat-model]]'s row asks for without
  charging an honest caller twice.

## Design

### The grammar

Six rules. A route that does not follow them is a bug in the route, not
an exception in the grammar.

1. **Plural resource nouns.** `files`, `uploads`, `shares`, `links`,
   `workspaces`, `events`. `admin` is the one prefix that is not a
   resource, because it is a viewpoint across every resource
   ([[012-administration]]).
2. **One owner per prefix.** Each top-level prefix under `/v1` is owned
   by exactly one spec, and the spec that owns the prefix owns every
   path under it. Links are under `shares` because a link is a grant
   ([[008-shares-and-links]]), not a resource of its own.
3. **A collection route takes no id; an item route takes `{id}`.** Ids
   are opaque strings the server minted and a client stores verbatim.
4. **A verb is a `POST` on a sub-path of the item**: `/complete`,
   `/attach`, `/sync`, `/restore`. Nothing is a verb in a query
   parameter, with the two read modes of `GET /v1/files/...` named
   below, which select a representation and not an action.
5. **Where a literal sits beside a wildcard in the same position, the
   literal wins and the word is reserved.** Four words are reserved by
   this rule: `materialize` is not an owner, `links` and `with-me` are
   not share ids, and `deleted` is not a workspace id. The router
   refuses to start if a fifth is added without a row here.
6. **A space appears at most once in a path.** `{owner}` is a subject,
   percent-encoded, or the alias `me`. There is no `org` alias: it read
   a claim for meaning, which invariant 5 of [[001-architecture]]
   forbids.

### Addressing a space

`{owner}` is the subject `<issuer>|<sub>` of [[006-identity]],
percent-encoded, so `https://issuer.example|9ab3` is
`https%3A%2F%2Fissuer.example%7C9ab3`. `me` resolves to the caller's own
subject. A response always renders the subject in full and never an
alias, so a client that stores what it read can send it back.

The `u-<uuid>` and `o-<uuid>` forms of the service Arca replaces are
gone with the claims that produced them ([[019-migration-from-drive]]).

### The route table

Forty-one routes under `/v1`, plus `GET /openapi.json`. `Action` is
the authorizer question of [[006-identity]]; `none` means the route asks
nothing, and the group says why. A route with several rows is one route
whose query parameters select a representation.

#### Files, trash, and stars ([[005-files]])

| Method | Path | Action | Does |
|---|---|---|---|
| PUT | `/v1/files/{owner}/{path...}` | `file.write` | write one object; the body is the bytes |
| GET | `/v1/files/{owner}/{path...}` | `file.read` | read one object: the bytes at or below `ARCA_INLINE_BYTES`, a `302` to a presigned URL above it; `?inline=`, `?download=` |
| GET | `/v1/files/{owner}/{path...}?list=1` | `file.list` | list the subtree at that path; `?cursor=`, `?limit=` |
| GET | `/v1/files/{owner}/{path...}?versions=1` | `file.read` | the versions of that path, oldest first; `?cursor=` is a version number |
| GET | `/v1/files/{owner}/{path...}?version=N` | `file.read` | read version `N` |
| HEAD | `/v1/files/{owner}/{path...}` | `file.read` | the object's headers with no body |
| POST | `/v1/files/{owner}/{path...}` | `file.write` or `file.restore` | `{"move_to"}` moves, `{"restore_version"}` restores; exactly one |
| DELETE | `/v1/files/{owner}/{path...}` | `file.delete` | trash the object; `?permanent=1` removes it, `?version=N` prunes one version |
| GET | `/v1/files/materialize` | `file.list` | the caller's own space as a manifest of presigned URLs; `?owner=`, `?prefix=` |
| GET | `/v1/trash` | `file.list` | what is trashed and still restorable; `?owner=`, `?cursor=`, `?limit=` |
| POST | `/v1/trash/restore` | `file.restore` | `{"owner","path"}` returns one object to its path |
| DELETE | `/v1/trash` | `file.delete` | empty the trash, or one path with `?path=`; `?owner=` |
| PUT | `/v1/stars` | `file.write` | `{"owner","path"}` stars an object; idempotent |
| DELETE | `/v1/stars` | `file.write` | unstar; `?owner=`, `?path=`; idempotent |
| GET | `/v1/stars` | `file.list` | the caller's stars across every space; `?cursor=`, `?limit=` |

`?list`, `?versions`, and `?version` select a representation of the same
object and are checked in that order. They are the one place a query
parameter changes what a `GET` returns, and they are kept because Go's
router cannot distinguish `files/{owner}/{path...}` from a sibling
collection route under the same wildcard.

Three more parameters shape a read without changing what it names, and
this spec owns them so [[005-files]] does not have to state them twice.
`?inline=1` asks for the bytes and is honoured only at or below
`ARCA_INLINE_BYTES`; above it the redirect stands, because invariant 4
of [[001-architecture]] is not a default a caller waives. `?inline=0`
asks for the redirect at any size. `?download=1` puts the path's last
segment into the presigned URL's content disposition, so a browser saves
the object under its own name rather than under a key. Any other value
for any of the three is `invalid_field`.

`GET /v1/files/materialize` is the route the service Arca replaces
called `userspace/materialize`. It reads one space and needs no lease,
because there is no writer to exclude ([[009-workspaces]] owns the
leased form).

| Method | Path | Action | Does |
|---|---|---|---|
| POST | `/v1/uploads` | `upload.write` | open a session; 201 with the part URLs |
| POST | `/v1/uploads/{id}/complete` | `upload.write` | assemble the parts into the object; 200 or 201 |

#### Shares and links ([[008-shares-and-links]])

| Method | Path | Action | Does |
|---|---|---|---|
| POST | `/v1/shares` | `share.create` | grant a subject a permission on a subtree; 201 |
| GET | `/v1/shares` | `share.list` | the grants on a space; `?owner=`, `?path_prefix=`, `?cursor=`, `?limit=` |
| GET | `/v1/shares/{id}` | `share.read` | one grant |
| DELETE | `/v1/shares/{id}` | `share.revoke` | revoke a grant; 204 |
| GET | `/v1/shares/with-me` | `share.list` | the grants whose grantee is the caller |
| POST | `/v1/shares/links` | `link.create` | mint a token grant; 201 with the token, shown once |
| GET | `/v1/shares/links` | `link.read` | the token grants on a space; `?owner=`, `?cursor=`, `?limit=` |
| DELETE | `/v1/shares/links/{id}` | `link.revoke` | revoke a token grant; 204 |
| GET | `/v1/shares/links/{token}/meta` | none | what the token names, before anything is fetched |
| GET | `/v1/shares/links/{token}` | none | a listing of the subtree the token names |
| GET | `/v1/shares/links/{token}/files/{path...}` | none | one object under the token's subtree |

The last three ask nothing and carry no bearer token. The grant row is
the authorization, and [[008-shares-and-links]] states the exception to
invariant 5 in full. `{token}` is a 256 bit value, so it does not
collide with `{id}` in practice; the router matches `links/{token}/meta`
and `links/{token}/files/...` by their suffixes and `links/{token}`
by method, since a bare `GET /v1/shares/links/{token}` and a `DELETE
/v1/shares/links/{id}` differ in method.

#### Events ([[010-events-and-reaper]])

| Method | Path | Action | Does |
|---|---|---|---|
| GET | `/v1/events` | `event.read` | the space's log, oldest first; `?owner=`, `?cursor=`, `?limit=` |

There is no route that reads or writes a limit, because Arca stores
none. A limit arrives on the authorizer's answer and a write past it is
`413` `quota_exceeded` ([[006-identity]]). A space's usage is read from
`GET /v1/admin/overview` ([[012-administration]]). This log is also
where an administrator's actions are recorded, so there is no audit
route either.

#### Administration ([[012-administration]])

| Method | Path | Action | Does |
|---|---|---|---|
| GET | `/v1/admin/overview` | `space.admin` | one row per space with its usage and its counts; `?cursor=`, `?limit=` |
| POST | `/v1/admin/spaces/{owner}/restore` | `space.admin` | restore one deleted object or workspace of that space |

Every other administrative read is an ordinary route of another spec
asked about a space the caller does not own: `GET
/v1/files/{owner}/{path...}?list=1` for its objects, `GET
/v1/shares?owner=` for its grants, `GET /v1/trash?owner=` and `GET
/v1/workspaces/deleted?owner=` for what it can still recover, and `GET
/v1/events?owner=` for what happened to it.

Outside `/v1`, `GET /openapi.json` serves the generated description
below and takes no token.

### Bodies and content types

A request body that is not object bytes is JSON, decoded with unknown
fields refused, so a client that misspells a field learns it at once
rather than silently writing a default. The decoder is
`httpjson.DecodeBody`, which maps an oversized body to `body_too_large`
and a syntax error to `bad_request`. Any content type other than
`application/json` on a JSON route is `unsupported_media_type`, and an
`Accept` that excludes JSON is `not_acceptable`.

Object bytes go to `PUT /v1/files/{owner}/{path...}` with the caller's
`Content-Type`, recorded verbatim and served back on read. That route
requires a `Content-Length`, because the usage admission of
[[010-events-and-reaper]] decides before the first byte is
written and a chunked body would make the decision a guess. A body
above `ARCA_MAX_UPLOAD_BYTES` is `object_too_large`, and a body above
`ARCA_INLINE_BYTES` should use the session of [[007-uploads]] instead.

Every JSON response is `application/json`. Every timestamp is RFC 3339
in UTC. Every byte count is a JSON number of int64 range.

### The list envelope and pagination

Every list route answers one shape, `{"entries": [...], "next_cursor":
"01J8R4..."}`.

`entries` is never null and is an empty array on an empty page.
`next_cursor` is present only when a further page exists, so its
presence is the only has-more signal and a client stops when it is
absent. A client sends it back as `?cursor=` unchanged; it is opaque and
its content is the server's business.

`?limit=` defaults to 100 and is capped at 1000. A `limit` above the cap
is `invalid_field` rather than a silent clamp, which is a change from
the service Arca replaces: a client asking for 5000 and receiving 1000
silently believes it has read everything.

`GET /v1/events` uses this envelope and this parameter too. The service
Arca replaces answered `{"events": [...], "next_after": 0}` and paged
with `?after=`, so the log had no has-more signal and a consumer polled
until an empty page. The tail of [[010-events-and-reaper]] is
the same keyset tail with `?cursor=` as its parameter name and
`next_cursor` as its answer. One envelope, one rule, no route exempt.

Pagination is keyset, never offset. The cursor is the sort key of the
last row of the page, so a page is stable under concurrent writes and
costs the same at row one and row one million.

A `list` action carries the authorizer's `filter` when one is returned
([[006-identity]]). The handler applies the filter to its own query, so
a selector outside the filter yields an empty page and never a 403.
The administrative overview applies none, because it asks `space.admin` and not a `list` action ([[012-administration]]).

### ETags and conditional requests

Every object read and every object write answers an `ETag`. Its value is
the object's checksum: the sha-256 of the bytes for anything Arca
streamed, and the store's composite ETag for an object assembled from
parts Arca never saw ([[003-object-store]], [[007-uploads]]). The object
body carries both parts, so a client can tell which it holds:

```json
{"path": "files/reports/q3.pdf", "size": 48213, "checksum": "9f2c...",
 "checksum_kind": "sha256", "content_type": "application/pdf",
 "modified": "2026-09-18T10:02:11Z"}
```

| Header | On | Effect |
|---|---|---|
| `If-None-Match: "<etag>"` | `GET`, `HEAD` | 304 with no body when the object still has that checksum |
| `If-None-Match: *` | `PUT`, `POST /v1/uploads/{id}/complete` | create only; an existing object is `precondition_failed` |
| `If-Match: "<etag>"` | `PUT`, `DELETE`, `POST .../complete` | write only if the object still has that checksum; otherwise `precondition_failed` |

No route requires a precondition. Every object under `files/` takes
these headers and none demands them, so the caller whose lost update
would be silent and expensive, typically an agent writing back state it
read, opts into the round trip and every other caller does not pay for
it ([[005-files]]).

The comparison is against the database row, not the bucket. The row is
the authority on existence (invariant 2), so a conditional write is one
SQL predicate and is atomic with the metadata write, while the bucket
write that preceded it wrote a fresh key that no live row references
until the predicate holds. A failed condition therefore leaves bytes
with no row, which the reaper removes
([[010-events-and-reaper]]).

Quotes are stripped before comparison, so a bare checksum is accepted
beside the quoted form. `ETag` is strong; nothing here is a weak
validator.

An upload session, from `201 POST /v1/uploads`:

```json
{"id": "01J8R4...", "owner": "https://issuer.example|9ab3...",

```

A workspace with its lease, from `200 GET /v1/workspaces/{id}`:

```json
{"id": "01J8R4...", "owner": "https://issuer.example|9ab3...",
 "slug": "build", "root_prefix": "workspaces/build/", "files": 812, "bytes": 40122388,

 "last_sync": "2026-09-18T09:41:02Z", "created_at": "2026-09-01T08:00:00Z"}
```

`lease` is null when no writer holds one. The service Arca replaces
carried `locked`, `writer_sandbox_id`, and a separate expiry across two
differently shaped responses for one resource; one nested object says
the same thing once.

A manifest, from either materialize route:

```json
{"root": "workspaces/build/", "pinned_at": "2026-09-18T09:41:02Z",
 "files": [{"path": "src/main.go", "checksum": "1a2b...", "size": 4210,
            "url": "https://bucket.example/..."}]}
```

`path` is relative to `root`. `pinned_at` is null on
`GET /v1/files/materialize`, which pins nothing. Every `url` is a
presigned `GET` valid for five minutes ([[003-object-store]]).

An event, from `GET /v1/events`:

```json
{"id": "01J8R4...", "action": "put", "owner": "https://issuer.example|9ab3...",
 "path": "files/reports/q3.pdf", "actor": "https://issuer.example|9ab3...",
 "detail": {"size": 48213}, "at": "2026-09-18T10:02:11Z"}
```

### The error table

The envelope is `latere.ai/x/pkg/httpjson`'s, written with
`httpjson.WriteError`:

```json
{"error": {"code": "precondition_failed",
  "message": "The object is not in the state the request required.",
  "details": {"request_id": "req_01J8R4...",
    "detail": "If-Match named 9f2c...; the object's checksum is 4d81..."}}}
```

One code, one status, one fixed sentence in `message`, and everything
that varies in `details`. `details.request_id` is always present.
`details.detail` is the developer sentence and is the only field that
names values, paths, or reasons; it is written for a person reading a
log and is never parsed. A code that names fields adds `details.fields`,
a list of the field paths at fault. `message` never varies, never
interpolates, and never leaks: a caller shows it to a person and
branches on `code`.

| Code | Status | `message` |
|---|---|---|
| `bad_request` | 400 | The request could not be read. |
| `missing_field` | 400 | A required field is missing. |
| `invalid_field` | 400 | A field has a value it cannot take. |
| `unknown_field` | 400 | The request body has a field this endpoint does not know. |
| `invalid_path` | 400 | That is not a path this server accepts. |
| `unknown_plane` | 400 | That path starts with a plane this server does not serve. |
| `exclusive_fields` | 400 | Two fields that cannot be set together are set. |
| `unauthenticated` | 401 | Sign in and send a valid token. |
| `forbidden` | 403 | You do not have permission to do this. |
| `not_found` | 404 | There is no such object. |
| `not_acceptable` | 406 | This endpoint answers in JSON. |
| `path_taken` | 409 | Something already exists at that path. |
| `slug_taken` | 409 | This space already has a workspace with that name. |
| `writer_held` | 409 | Another writer holds this workspace. |
| `lease_not_held` | 409 | This attachment does not hold the writer lease. |
| `manifest_incomplete` | 409 | The manifest names objects that have not been uploaded. |
| `attachment_gone` | 410 | This attachment has ended; attach again. |
| `length_required` | 411 | Send a Content-Length with the body. |
| `precondition_failed` | 412 | The object is not in the state the request required. |
| `object_too_large` | 413 | The object is larger than this server accepts. |
| `body_too_large` | 413 | The request body is larger than this server accepts. |
| `quota_exceeded` | 413 | This space has no room left. |
| `unsupported_media_type` | 415 | Send the body as JSON. |
| `too_many_parts` | 422 | The object needs more parts than this server allows. |
| `link_read_only` | 422 | A link grants reading and nothing more. |
| `rate_limited` | 429 | Too many requests; wait and retry. |
| `internal` | 500 | Something went wrong on this server. |
| `not_implemented` | 501 | This server does not serve that. |
| `storage_unavailable` | 503 | Storage is unavailable right now; retry shortly. |
| `authorizer_unavailable` | 503 | The permission service is unavailable; retry shortly. |

Rules the table is held to. A test reads this file and fails on any
violation.

- No handler writes a `message` outside the table, and no code appears
  with two statuses. `quota_exceeded` is `413` and not a class of its
  own: the space cannot take a body of that size, which is the same
  answer as `object_too_large` reached by a different measure. It is
  returned only when the authorizer's answer carried a
  `limits.quota_bytes` the write would cross ([[010-events-and-reaper]]);
  Arca stores no limit and refuses no write for size without one.
- `not_implemented` is a route this installation registers and does not
  answer. It is the one code whose cause is the build rather than the
  request, and a caller retries nothing on it. Two things reach it: a
  route whose behaviour belongs to a spec that has not landed, which is
  how the frame registers a route at its right place and with its right
  verifier exception before the handler exists
  ([[019-migration-from-drive]]'s phases), and a route an installation
  turns off. Nothing else answers it, and no handler that works answers
  it at all.
- A refusal is `forbidden` when the caller's own action was denied and
  `not_found` when a reference the request named was denied at lookup,
  which is invariant 6 of [[001-architecture]]. The two are
  indistinguishable from a missing object by design, and a 404 from a
  deny is byte for byte a 404 from an absence.
- Nothing above 499 names a store, a query, a key, or an internal type,
  even in `details.detail`.
- The service Arca replaces answered `{"error": "<sentence>"}`, a flat
  string with no code, and two routes answered a machine code in that
  same field with a sibling key beside it. Every error site changes
  shape. That is the largest single break in this spec and the reason
  [[019-migration-from-drive]] moves the consumers in one step.

### The request id

Every request has one, `req_` and a ULID. A client's `X-Request-Id` of
at most 128 printable ASCII characters is kept; anything else is
replaced. It is the `details.request_id` of an error, the `request.id`
the authorizer sees ([[006-identity]]), the event's request id, and the
trace's correlation ([[018-observability]]). Every response carries it
back in `X-Request-Id`, errors included.

### OpenAPI

`api/openapi.yaml` is generated from the code and committed, and `GET
/openapi.json` serves the same document as JSON. It takes no token: a
route name is not a secret, and existence hiding protects objects, not
the shape of the API.

The document is built as Go values in `internal/apidocs` and rendered by
the standard library, so the server serves it without an embedded file
and without a YAML parser on its build list, which invariant 9 of
[[001-architecture]] would otherwise have to admit. `tools/apidoc` is
the one place a YAML encoder is reached, and it renders the same
document to the committed file. The served document and the committed
one differ in one member: the served one names `ARCA_PUBLIC_URL` as its
server, and the committed one names none, because a file in a
repository describes no one installation.

The generator takes three inputs and no hand-written path list:

| Input | Source |
|---|---|
| the route set | the route table of `internal/api`, the declaration the mux is built from |
| the schemas | the Go request and response types, by reflection, in their declared field order |
| the errors | the code table of `internal/api`, which a test holds equal to the table above, one response per code |

The route set is a declaration rather than the `mux.HandleFunc` calls
read out of the source with a regular expression, which is what the
service Arca replaces did. One table is registered, described and
tested, so the document and the registrations cannot disagree and there
is no second reading of the source to keep in step.

The error table is read from `internal/api` rather than from this file
for the same reason: a test in that package already holds the Go table
equal to the table above, so generating from the Go table is generating
from this document with one fewer file read at build time.

`make openapi` regenerates it. The gate fails when the committed file
differs from a fresh generation, so a route added without regenerating
does not reach `main`. The e2e tier of [[014-test-stubs-and-tiers]]
validates every request and every response it makes against the
document, so a handler cannot drift from it either.
